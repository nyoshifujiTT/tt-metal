# Qwen3.8-Flash-Next decode on one Blackhole Galaxy — the round model (27B README 方式) と 5 軸並列の限界

この文書は、`models/demos/blackhole/qwen35_27b_glx/README.md`（Qwen3.5-27B、データフロー第一）の §1〜§12 の方式をそのまま本モデル（MoE + GDN）に適用した限界性能の**現在の確定状態**を書く。物理値と HF 定義だけから机上で出し、実装の実測値は入れない（27B §1-3）。経緯・実測・議論は作業記録 `/opt/codex/shared-with-lxd-containers/BH-GLX_Qwen3.8-Flash-Next_SC1_handoff_worklog_20261023.md` §10.R（追記専用）、生成器は `BH-GLX_Qwen3.8-Flash-Next_round_model_20261024.py`、routing の分子は `..._routing_census_20261023.py` → `..._routing_stats_20261023.py`（`..._routing_stats_full_20261023.json`）。この文書は `render_round_readme.py` が同じ入力から決定的に生成する。

## 1. 大原則（27B §1 と同じ）

1. **全 chip の DRAM は常に動き続ける。** 各 chip は次の計算に使う重みと状態を自分の DRAM から 512 GB/s で読み続け（更新した状態はその帯域で書き戻し）、演算も通信もその読み書きに追従するだけ。起こり得る唯一の違反は L1 の「あふれ」。
2. 1 周の時間は先に決まらない。DRAM の窓/512 GB/s で決まる。
3. 設計値は物理値（帯域・レイテンシ・L1/DRAM 容量・Tensix の cycle 単価）と HF 定義から出す。実測は合格判定にだけ使う。
4. 割付は単品を容量比で詰める。
5. GDN の状態 S は fp32 で全部 DRAM（1 ユーザ 1 層 [48,128,128] = 3.0 MiB、36 層 108 MiB、32 ユーザで 3.62 GB: L1 には入らない）。毎 token 読み→更新→書き戻し。

## 2. 本モデルで 27B と違う点（MoE）とその扱い

- **(M1) routed expert は router の後にしか読めない。** dense（5.378 GB）は先読みできるが routed（top-10 × 2.76 MB × 49 層 × distinct）は層 l の router（= その層の attention/GDN 側が終わった時刻）まで何を読むか分からない。枠の窓にはこの「router 後の区間」が入るので、DRAM を止めないには **router の前に読み終えている**（投機 routing の先読み、または全 expert を毎 step 読む）必要がある。3 ケース + 1 を並列に出す: 全ミス（router 後に読む = 今の runtime の形）／census ヒット率 h（1 ブロック早い投機 routing の実測ヒット率 B=1 0.78 〜 B=256 0.94、外れ分は router 後に再読み）／全ヒット／全 expert 読み（router 依存ゼロ）。
- **(M2) expert の分担は段の全 chip で列方向に等分（TPx = 段の chip 数）。** expert を chip に丸ごと置く EP は token ごとの偏り（census: 4 group 分割で最繁忙 group が平均の 1.04（B=256）〜1.67（B=1）倍）の分だけ最繁忙以外の chip の DRAM が寝るので原則 1 に反し、候補にしない。
- **(M3) B で routed の量が変わる**（distinct(B): B=1 10、16 124、32 199、256 426）。周の窓は B ごとに別で、tsu/agg は B の関数。
- **(M4) S の往復（1 ユーザ 0.231 GB/pass）が B に比例**して列に乗る。27B の「S の往復 26%」と同じ構造で、B=128 で列の 1/3。
- **(M5) MTP**: verify 行 R = k+1、採択 R_eff tokens/pass（k=1 で 1.376 = 本件のプロンプト集合の採択率）。

## 3. 機械の物理値（27B §3 と同じ値、出典も同じ）

DRAM 512 GB/s/chip（読み書き和）、31.9 GiB/chip；chip 間 link 25 GB/s × 2/方向 × 4 方向（8×4 torus）；1 hop 280 ns + 蓄積転送 2 KiB/(96 B/cycle) = 16 ns、中継 NoC 64 B/cycle・92 cycle；Tensix 130 core × 1.35 GHz、行列積 33 cycle/32×32 tile-MAC（HiFi2）、要素演算 16 cycle/tile、op 固定 300 cycle、gated delta rule 400 cycle/(value head, user, S の 32 列) + 1,100/層；L1 1,536 KiB/core、固定専有 140 KiB/core + 活性の置き場（27B の値）。

## 4. 手順 1〜3: 列、周数と窓、同時に動く台数（TP）

## 5. 手順 4〜5: 通信、routed の露出、あふれない条件

- 通信（27B §11-2/11-4/11-5 の式）: 層に all-reduce 2 本（attention/GDN ブロック後、MLP ブロック後。reduce-scatter → 残差 → all-gather を 1 本、両方向 ring + 隣の環の中継で 4 経路、tile 流しで K チャンク演算の下に隠す、隠れない分 = link − 隠れた分 + 最後の tile のレイテンシ 2 × last_tile(tp/2 hop)）。1 行 [rows, 2560] bf16 の 1 本: TP4 link 0.08 µs + レイテンシ 1.37 µs、TP8 0.09 + 2.92、TP16 0.10 + 6.02（rows=1）。段の受け渡し（枠境界ごとに残差 [rows, 4H]/tp を隣の環へ 1 hop）は 1 token で 8 回、B=1 で 0.4%。
- routed の露出（M1）: 全ミスでは層ごとに distinct × 2.76 MB / tp を router 後に読む時間が依存鎖に乗る。census では (1−h) 分。全ヒット・全 expert 読みではゼロ。
- (4) あふれ: 鎖が DRAM 時間を超える分を枠数で割った「段の始まりの遅れ」≤ 枠の余り/512 GB/s。(5) 書き戻しの番: 枠あたりの鎖 ≤ 窓 + min(余り + dense 部, 窓)/512 GB/s。
- DRAM-bound = 鎖 ≤ DRAM 時間（原則 1 が成り立つ: token 時間 = 周数 × 窓）。

## 6. 結果（ctx 192、TP8 × PP4、分子は census 全数）

- **tsu の限界（B=1, k=1）**: 全ヒット **2,861**（1 token = 周 2 × 窓 240 µs = 0.481 ms、DRAM-bound）；census ヒット率 2,327（鎖 0.591 ms > DRAM 0.507）；全ミス 1,356；全 expert 読み 301。k=0 全ヒット 2,263。
- **agg の限界（DRAM-bound で (4)(5) を満たす最大）**: 全ヒット **34,325**（B=256×1 行、tsu 134、周 19）；census 33,424（B=256×1、tsu 131）；全 expert 読み 31,399（B=256×1）。
- **今日の形（B=16×2 行、全ミス）**: 185 tsu / 2,966 agg が机上の値（鎖 7.42 ms のうち routed 露出 5.94）；全ヒットなら 662 / 10,590、census なら 571 / 9,133。実測 1,186.9 t/s（DP8×TP4 lanes16）は全ミスの机上値の 40%、全ヒットの限界の 11%。
- 5 軸の答え: **TP = 8（演算を DRAM に追いつかせる最小台数、B に依らない）、PP = 4（残り）、EP = 1（段内で列方向等分、偏りゼロ）、CP = 1（ctx 192 では KV が列の 1% 未満。長文脈では KV が列に乗るので周数が増え、CP は「KV を段内で分担する」形でこの枠組みに入る）、DP = 1（同じ token 集合が全段を通る周モデルでは DP は B の中に吸収される: B 人を 1 まとめで流すのが DP の代わり）**。B は tsu と agg のトレードオフ（B=1 で tsu 最大、B=256 で agg 最大）。
- 本件固有の前提: **routed を router の前に読み終える仕組みが無ければ、どの B でも DRAM は寝る**（全ミスは限界の 1/2.5〜1/6）。投機 routing（ヒット 0.78〜0.94）なら B≥32 で DRAM-bound、全 expert 読みなら全 B で DRAM-bound だが tsu は 1/10。
